# 知径 Demo：任务化功能验收与研究边界

更新日期：2026-10-31
适用对象：仓库现有 `concept-dictionary/` 本地单用户原型。本文用于安排可复现的功能核查，不是新的产品需求、教学脚本或用户研究方案。

## 1. 目的与研究问题

知径把用户明确选择的已知义项作为起点，展示词典超图中的定义依赖路径。任务化验收要回答两个分开的工程问题：

1. 当前界面是否忠实呈现索引所记录的义项、AND 联合前提、OR 替代分支、循环和来源状态？
2. 哪些界面措辞、分支默认选择或路径状态可能让用户把图计算结果误读成词义真值、蕴涵或学习顺序？

自动化功能通过只能支持第一个问题的一部分。它不能证明图中的释义与依赖关系语义正确，也不能证明用户理解了概念或学会了目标词义。

## 2. 当前实现证据

核查依据为当前仓库代码与测试：

- `backend/reasoning.py` 将每个分支解释为联合前提，并在不同分支中选择可达路径；循环不会在无种子时自举。
- `backend/app.py` 对解释树按已选分支计算可达状态，避免从未选择的分支借用可达路径；返回节点状态包括 `known`、`cycle`、`missing`、`no_definition`、`limit` 等。
- `frontend/src/Explanation.tsx` 展示定义、完整分支前提、分支选择器、来源入口；介词或介词短语显示风险提示，循环、缺节点、无定义与节点上限有状态提示。
- `frontend/src/ExplorePage.tsx` 把结果标为“图中可达”，并提示可达不表示已经理解或推荐的学习顺序。
- 现有后端测试使用合成图覆盖 AND、OR、多步展开、循环、选中循环不能借未选分支脱困、增量可达与会话合法性。
- 现有前端测试覆盖介词风险提示、AND/OR 文案、路径中介词定位及分支标签。此处并无完整浏览器端到端测试结果。
- `docs/cases.md` 中真实图案例只是结构与来源映射核查；square 案例明确出现 `right` 义项匹配问题，不能作为语义金标准。所有真实图任务执行前都要复核图指纹、来源可用性和目标义项。

## 3. 固定任务集

每项任务使用同一数据指纹和同一应用版本。记录操作前置条件、用户动作（若仅做工程核查则记录自动化动作）、屏幕呈现、后端响应、目标分支与每个依赖 occurrence 的标识。任务中的成功只表示界面/计算满足验收条件。

| ID | 任务 | 可复现输入/前置条件 | 功能验收标准 | 当前自动证据 | 尚未验证 |
|---|---|---|---|---|---|
| T03-01 | 搜索并区分同形义项 | 搜索存在多个义项的词形；每项记录返回 ID、POS 和 gloss | 用户可看到并选择具体义项；后续解释与该 ID 绑定；不得默认为词形级单一含义 | HomePage 存在义项结果选择；本轮未发现涵盖搜索到选择的端到端断言 | 真实索引上的排序、完整候选覆盖、键盘及窄屏操作；用户是否能辨析义项 |
| T03-02 | 查看目标 gloss 与来源 | 从一个可用目标义项打开解释，打开来源侧栏 | 展示 gloss、sense ID 和来源可用状态；文件缺失时明确提示；出处信息可回指对应记录 | Explanation 有定义与来源入口；发布准备文档记录索引指纹机制 | 真实图下来源映射逐例抽查；不同数据版本的端到端展示 |
| T03-03 | 比较 AND 前提与 OR 分支 | 合成固定图：`target -> {a,b}` 或 `target -> {c}`；分别以 `{a}`、`{a,b}`、`{d}` 为已知，其中 `c -> {d}` | 仅 `{a}` 时第一分支未完整满足；`{a,b}` 可满足第一分支；`{d}` 可经第二分支多步满足；切换分支后所选索引及完整树同步变化 | reasoning 与 explain 测试覆盖 AND、替代分支、多步展开；界面测试检查 AND/OR 标签 | 真实图的分支释义保真；用户是否理解“完整前提”不是上下文必须逐词出现的清单 |
| T03-04 | 识别循环、缺失节点与不可达状态 | 合成循环 `cycle_a -> cycle_b -> cycle_a`；另加缺失前提；指定不同已知集合和分支 | 循环节点显示循环状态；缺失前提不被当作已满足；所选循环分支不可借未选分支完成；闭包不凭空产生新起点 | 后端 explain 与 reasoning 测试覆盖 selected-cycle 和无种子循环；节点状态在组件中有对应提示 | 浏览器实际状态转换、长路径上限提示及真实图边界案例 |
| T03-05 | 审视介词、方向、否定与角色风险 | 选取已来源定位的介词/介词短语依赖，至少包含一个方向/角色例和一个否定/缺失例；来源不明确的项目标 `unresolved` | 界面明确提示需回看来源；不得把介词节点只当无方向的主题关联；记录原分支、论元顺序和否定范围，不能只记录“有/无介词” | 界面和测试只证明存在通用风险提示与路径节点定位 | 当前 Demo 没有关系类型标签、语义审核状态或独立保真结论；例项选择和定义保真仍待盲审 |

任务 T03-05 与 T02 共享问题清单，但知径中看到一个节点或提示不等于完成了 T02 的独立盲审。T02 的正式标签不得由该界面或已有 40 条试标自动生成。

## 5. 阶段和验收门

### Gate A：代码级任务覆盖（当前阶段）

- 对上述五项任务建立输入与功能验收标准。
- 将现有测试的覆盖范围和空白明确对应到任务，不用代码检查推断实际运行结果。
- 验收：文档可指导另一个研究者复现任务；合成图任务与真实数据任务区分明确。

### Gate B：真实图人工操作核查（待执行）

- 只在许可可用的冻结数据本地启动；核验数据指纹后选取真实义项。
- 工程核查者按固定步骤运行任务，逐项比较预期 ID/分支/occurrence 与 UI/API；记录错误、缺失来源、布局遮挡和无法判读。
- 此阶段不采集学习结果，不用测试标签或旧试标标签调参。

### Gate C：可用性/理解研究（未获批准前不启动）

- 需先明确研究问题、目标人群、研究者、样本计划、同意与隐私保存方案及伦理要求。
- 任务成功率、操作时间、路径复述正确率、信心和误解类型应预先定义；与无结构 gloss 或其他对照的比较需随机化或合理配对。
- 只有合适的人类行为数据才能支持“用户理解/学习改善”；本项目当前没有此类数据。

## 6. 已知风险与停止条件

1. **数据语义问题：** 依赖边和闭包只表示计算关系，不代表蕴涵或真实学习顺序。遇到 sense mismatch、方向翻转、否定范围丢失或无来源证据，标为 `unresolved` 并停止将该项当示范金标准。
2. **输入泄漏与数据保护：** 冻结 OEWN 保持只读。记录文件指纹，不把原始包、私人来源、用户状态 JSON 或截图推入 Git。
3. **结论越界：** 单元测试通过只能支持对应代码行为；模拟任务通过不能支持人类理解或认知发展结论。
4. **停止条件：** 如果目标义项/来源不能确认、输入指纹变动未解释、数据许可不清或任务无法复现，停止该任务并记录原因；不得用其他案例悄然替换。

## 7. 本轮结论

本轮完成了可执行的验收任务定义，并用本机 API 在既定冻结指纹上完成搜索、三目标八分支和一个指定循环路径的只读试跑。自动化证据、API 试跑和待浏览器/语义/参与者核查均分开记录。没有运行浏览器任务，没有独立审核真实定义，没有招募参与者，也没有宣称 Demo 改善了学习效果。下一步复核 API 的真实来源内容，补做错误/边界路径和键盘/窄屏检查，并把每项失败转成可定位的代码或数据问题；Gate C 需另行批准。
