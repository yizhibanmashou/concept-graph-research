# ToLogic 候选语义盲审协议 v1

**状态：** 标注前协议；尚无人工标签。
**适用对象：** 现有 `want` / `be without` 单案例的候选公式探索。
**目标：** 判断导出的候选公式能否在给定词义、定义、两个使用例和参数接口下，作为目标概念的合理逻辑表达；定位错误类型。该流程不是标准 benchmark，也不估计整个引擎的准确率。

## 1. 研究问题与证据边界

主问题是：对一个目标义项，有限枚举器产生的公式是否保留了定义的必要语义，并能覆盖给定用例？具体案例额外关注 `without`：若它作为用户提供的外部接口，公式是否正确调用该接口、保留角色方向和否定含义？

六个已确认案例的 455 条候选、`want` 的 130 条候选、候选集合重放一致、公式树与 occurrence 的结构审计都属于工程或结构证据。它们不能证明公式可接受、定义保真、模型泛化或相对其他系统更好。`without` 的右侧语义目前未独立认证；接口约定本身若不足以判定公式，标注者应选择“不确定”，不得把枚举器的假设补成语义事实。

## 2. 本轮对象与样本

- 输入案例：本地 `model/cases/want_lack/input.json`，定义和使用例以该文件哈希所指向的快照为准。
- 候选总体：本地 `model/cases/want_lack/out/candidates.jsonl`，此前记录为 130 条；正式准备时必须重新计算行数并记录输入、候选文件 SHA-256。
- 初始样本：既有固定随机种子 17 的 20 条抽样，仅作为审阅流程试运行/可行性样本。随机抽取使每个候选有相等抽中概率，但单一案例和小样本不能代表其他词义、候选分布或未来版本。
- 参考表达式、候选 ID、自动语义接受字段和内部 oracle 不得提供给标注者。候选呈现次序随机；审阅表仅使用随机 `review_id`。
- 不根据审阅结果改写本批候选后再把相同样本当作独立验证。后续修订必须产生新版本、新摘要和新样本。

若源输入的语义前提（特别是 `without` 外部接口及其参数绑定）没有可审查来源，本轮可评价“在明示接口假设下的条件性适配”，不能评价未经限定的自然语言真值。

## 3. 标注单位与操作定义

**一个单位是一条完整候选公式**，标注者同时看到目标定义、lemma、两条使用例、参数说明和公式。公式中所有联合输入、替代路径、参数绑定和否定/关系运算都作为整体判断；不能把单个节点被图收录或公式通过语法检查视为正确。

### 主标签 `judgment`

- `acceptable`：公式在给定接口假设下表达目标定义的核心概念，且没有实质性角色/方向、否定、量词范围或必要条件错误；两个使用例均可与该公式相容。无需与某一参考公式逐字或逐树相同。
- `unacceptable`：至少有一个由材料支持的实质语义冲突，或公式遗漏定义中的必要区分/引入定义不支持的限制，足以使公式不再是该目标义项的合理表达。
- `uncertain`：材料不足、接口未认证、定义或用例存在歧义，或标注者无法有把握地裁定。不能为提高接受率而强迫二选一。

### 诊断轴 `diagnostics`

每轴取 `pass` / `problem` / `uncertain` / `not_applicable`；轴是错误定位，不替代主标签。

| 字段 | 要判断的问题 |
| --- | --- |
| `usage_a` | 候选是否与使用例 A 的目标用法相容？ |
| `usage_b` | 候选是否与使用例 B 的目标用法相容？ |
| `role_direction` | 参与者、论元和关系方向是否符合定义/用例？ |
| `negation_scope` | 否定、缺失或 `without` 是否保留，作用范围是否合理？ |
| `quantifier_binding` | 量词、变量和参数是否绑定到正确参与者/范围？ |
| `definition_completeness` | 公式是否保留定义所需的核心条件/联合输入？ |
| `unsupported_conditions` | 是否添加定义不支持的条件或不必要的限制？ |

`reason` 用简短文字说明证据，优先指出定义或具体用例片段与公式部分之间的对应关系。不得写入对隐藏参考答案的猜测。

## 4. 双人盲审及仲裁

1. 由组织者从同一个冻结导出文件生成两份独立副本，仅标注者编号不同；两名标注者不得在提交前讨论。
2. 每人独立填写全部主标签、诊断轴和理由。遇到材料缺失或接口依赖时使用 `uncertain`，不要自行补充关系规则。
3. 提交后锁定并保存两份原始标注，不覆盖、不平均、不将一人结果改成另一人的结果。
4. 汇总主标签分歧及各诊断轴分歧。分歧项交给第三人或研究负责人查看原材料并给出单独仲裁标签与理由；原始标签永久保留。
5. 先报告主标签原始一致率、三类标签混淆表及分歧数；诊断轴分别报告分布。若样本量/类别分布足以支撑，再补充适当的一致性统计并附区间与局限。20 条试运行不得包装成可靠的一致性估计或系统准确率。

仲裁结果是本案例的人工判断，不是独立 benchmark gold。只有另行预注册样本框、独立目标、标注手册和充分样本后，才可讨论确认性性能评估。

## 5. 报告口径与停止条件

报告必须给出：源文件和候选文件 SHA-256、版本/样本种子、总体与抽中数量、排除项、两位标注者原始主标签、分歧与仲裁、诊断轴计数、可复现命令，以及至少若干失败类型的去标识化摘要（如可公开）。不得只报告“接受候选数”，也不得将该比例称作准确率、精确率或泛化能力。

若标注者无法在不查看隐藏答案的情况下理解输入接口，或关键语义依赖未经认证的外部接口，则停止对该部分作确定性语义评价，记录为 `uncertain` 并先补齐接口定义/来源。若公开权利不清，审阅结果及含释义/公式的材料只保留在本机受忽略目录，不提交 Git。

## 6. 本机导出和资料管理

从仓库根目录运行，`--out` 必须是不存在的新目录：

```powershell
python hypergraph_analysis_exploration/research/tologic/blind_review.py `
  --input hypergraph_analysis_exploration/research/tologic/model/cases/want_lack/input.json `
  --candidates hypergraph_analysis_exploration/research/tologic/model/cases/want_lack/out/candidates.jsonl `
  --size 20 --seed 17 `
  --out hypergraph_analysis_exploration/outputs/want_review_protocol_v1
```

将 `review.json` 分别复制到标注者私有目录；`private-key.json` 仅组织者持有，绝不发给标注者、不得纳入 Git。标注结果也留在 ignored `outputs/` 或其他本机受控目录。公开仓库只保存本协议、代码和不含释义/候选/标签的汇总统计。
