# SemCor 开发集的两个简单 WSD 对照

首版协议在首次读取开发句子与标签前固定，但首次实现错误地从 gold sense key 取得目标 lemma，造成答案相关信息进入候选构造；首版开发结果作废。以下修订是看见首版结果后的纠错，开发集已用于发现问题，不是干净的最终验证。继续沿用 SemCor 文档种子 17 的 train/dev/test 划分；只用 train 统计词义次数，只在 dev 做探索性诊断，test 文档的句子和标签仍不读取。此划分来自 SemCor 自身，不是统一 WSD 标准测试集。

两个固定对照：①训练集中该 lemma/POS 候选的最高频义项（MFS）；未出现的候选频数为 0；②用该句子与同一候选集原始 gloss 的 BM25 词面重合排序，全部零重合时按候选 ID 升序选择。两者平分均按候选 ID 升序。候选使用语料表面词形、语料标注的 Penn POS 和 WordNet 3.0 `morphy` 推断 lemma，大小写折叠、下划线转空格；形容词 `a/s` 按同一大类。预测时不读该实例的 gold lemma、sense key 或 synset；评分才用 gold key 映射 OEWN。原始 `rdf` 实体标注与无法处理的 POS 单列排除，以避免将实体类型作为表面词义候选。

记录开发集标注数、实体／POS 排除数、key 未映射／歧义、目标不在图、目标不在候选及覆盖数；分别报告有覆盖样本准确率和将无法预测计为错误的合格样本准确率。按同一实例配对比较两基线；这不是标准 all-words 结果，数据处理口径已在观察开发集后修订，不能用于独立验证或确认性声明。

无语义真值的 `a/s` 合并不证明图与 WordNet 义项等价，候选覆盖与模型预测分开记录。输入版本、文档划分和工具版本均记录摘要；语料、模型输出和结果放本地忽略目录，不向 GitHub 上传。

修正后首次开发集结果出现较大基线差异；随后追加事后诊断，按候选数为一／多以及训练集中 lemma/POS 是否出现分别汇总，并记录两基线同时正确、各自独有正确与均错误的配对计数。这些分层和配对结果是事后分析，不能作为确认性检验。

重复运行时发现 BM25 原实现按无序词项集合累加浮点数，进程哈希顺序可能改变极近分数的排序。现改为按词项排序累加，并废弃此前非确定性输出；修正后分别在不同 `PYTHONHASHSEED` 下复跑检查。
