# 开发集 A–D 词袋消融试点

本协议在本次 A–D 开发集计算前写定，但开发集已经在早期开发中用于发现数据泄漏、实现修复和描述性分层，因此所有结果仅属探索性，不能作为独立检验。保留测试文档句子和标签不得读取。

以 `semcor_dev_pilot` 修正后的表面词形、已标注 POS、WordNet morphy 和形容词 a/s 口径构建候选，不读取本实例 gold 选择候选或预测。每个候选以图中原顺序贪心保留完整一跳分支，使 A、B、C、D 的紧凑 JSON 均不超过 **256 个 BERT uncased WordPiece**（包含候选侧特殊 token）。B/C/D 使用相同的已选依赖与 gloss：B 为依赖文本，C 加普通成对边，D 加完整分支。若任何候选的基础表示本身超预算或缺图数据，则该实例在所有条件下共同排除；未保留任何结构分支的候选仍保留并单独统计。

每种条件对同一候选集合建立 `GlossIndex` BM25，按句子与候选 JSON 的词面重合检索；零分候选按 ID 确定性排序。JSON 的键、ID 和符号参与词面化，不同条件的词项不同；BM25 是词袋模型，不理解 AND/OR、方向或角色。因此 C 与 D 的差异可能来自标记词、ID 重复和序列化，而不能证明结构推理。总预算只约束候选 JSON，句子不做 Transformer 拼接或截断；不能说已经控制真实编码器的联合输入预算。

同时记录可解析合格实例、排除和候选覆盖、各条件预测正确数、共同预算下结构分支覆盖、可重复的输入摘要、软件版本。仅对有 gold 且覆盖的开发实例评分；所有无法覆盖的实例按错计时另报分母。报告 one-candidate 与 multiple-candidate 两个子集，不能把容易的单候选样本当作词义区分表现。当前设计不做训练、不看保留测试标签、不报告显著性或正式 benchmark。

首轮结果后追加事后诊断：计数 gold 目标候选的分支保留状态，并记录 A、D 两条件各自单独预测正确的实例数。该结果不作为预先固定的主要指标。
