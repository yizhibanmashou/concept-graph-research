# 单个依赖节点删除的分支碰撞：探索性协议

问题：一个目标的两个原始非空分支，是否仅因某一个依赖节点不同；如果移除这个节点，它们是否变成相同的非空依赖集合？这种结构风险是否只涉及介词？

固定输入为本地 `OEWN/graph/nodes.tsv` 和 `hypergraph_rules.jsonl`，使用文件 SHA-256 记录版本。单位是目标 head；对于每个 head，先将分支转为去重的依赖 ID 集合，去掉原本重复的分支。每次只删除一个依赖节点：若长分支删除该节点后恰好等于同一 head 的另一条原非空分支，则该 head 计入这个节点的碰撞影响。新空分支单独计数，不作为非空碰撞。多对分支对同一 head 和节点只计一次。

同时记录每个节点出现过的 head 数、导致至少一次碰撞的 head 数，以及造成空分支的 head 数。按节点词性分别列出 `prep`、`prep_phrase` 和其他节点，报告总体、节点级频数和使用率。节点分类是词典现有 POS，不代表其语义功能。多次使用、共享源文件和同一词形的义项不独立；这里不做显著性检验或因果推断。数值既不是语义等价标注，也不证明去掉节点更清晰。

该协议在首次全图运行前固定。输出只存本地忽略的 outputs；发布前应检查输入权利和输出内容。结果不是对完全删除所有介词的重复实验：单节点干预可以辨认哪些单个依赖承载分支区分，但不会捕获必须同时删除多个节点才出现的碰撞。

首次运行发现单节点非空碰撞为零后，补充事后分析：将所有 `prep` 同时删除，按每个目标上发生碰撞的原始分支对计算对称差的节点数；逐目标取最小值。此分析用于解释既有整体介词删除结果，不是预先注册的独立假设检验。删除 `prep_phrase` 或其他依赖不会计入此分析。
