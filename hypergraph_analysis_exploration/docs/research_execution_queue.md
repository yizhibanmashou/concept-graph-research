用途：作为总控的可持续更新队列；记录可验证的下一步、依赖、停止条件和 GitHub 交付边界。本文不把计划写成结果，也不授权测试数据解封、标注数据分发或人类参与者研究。

## 总控问题与证据级别

**核心问题：** 保留定义中的联合构造（AND）、替代分支（OR）与可复用中间概念，是否比原始释义或普通成对关系，为机器语义理解与人类概念习得提供额外信息？

所有结果必须注明证据层：结构描述、模型工程/表示结果、独立语义结果、或人类认知结果。前一层不能替代后一层。所有支线保持一个主题一个分支/PR；数据、报告、checkpoint 和冻结 OEWN 不入 Git。用户已允许在检查无误后不强制 1 人批准并直接合并；但科学决策仍由用户把关，工程 CI 不能代替科学授权。

## 下一步工作单

### Q1 — T02 全量影响框之后的来源 crosswalk（当前主任务）

**已具备的可复核证据**

- 全量审计脚本：`src/analysis/audit_t02_full_oewn_prep_overlap.py`。
- 总体：104,907 个标准 POS 且冻结定义非空的 OEWN 目标；索引身份覆盖 104,907/104,907；109,497 个来源 payload checksum 和 payload identity 均通过。
- raw definition 与固定 OEWN 2025 Plus 释义精确匹配：104,886；未匹配 21。effective definition 精确匹配 101,354、非空不同 3,553。
- `prep` 删除影响 84,976/104,907 个目标；删除 198,543 个 occurrence，改变 116,616/145,991 个分支，生成 358 个新空分支；462 个目标有新增非空碰撞，collision excess 566。
- `prep_phrase` 敏感性口径相对 `prep` 额外影响 52 个目标，增加 303 个删除 occurrence、85 个改动分支、9 个新空分支和 1 个 collision excess。
- 聚合产物仅在 ignored `outputs/t02_full_oewn_prep_overlap_20261031.json`，SHA-256 `969c908f796eff082c51dc141b8f9e68c0abedcee4e4437bf1d769d853bda3cc`。这是有限总体结构/字符串审计，不是语义保真或来源权利证据。

**下一动作**

1. 从可确认的上游记录建立 `target → source payload → 原始 provider/release/version → license/attribution → source family` crosswalk；精确 OEWN 释义命中单独记录，不能据此推断 frozen payload 的唯一上游来源或权利状态。
2. 为 crosswalk 增加互斥失败类别：`exact_release_match`、`normalized_only`、`different`、`missing_identity`、`source_unresolved`、`rights_unresolved`。只输出聚合结果和哈希；标识符/释义仅在本机访问受控材料中使用。
3. 先根据用户已决定的目标等权、目标内分支比例平均，做标签揭盲前的精度/工时情景表。有限总体设计需以“目标”为抽样单位，把分支数作为每个目标的工作量；来源家族相关性和无法判断率另作设计效应/敏感性情景。
4. 用户确定可接受区间半宽/资源上限后，冻结总体、层、抽样概率、双标/仲裁和呈现盲化方案；抽样前核验权限和预注册状态。未通过时停在 crosswalk 与匿名聚合，不导出任务包。

**PR 切分**：`codex/t02-source-evidence-audit` 当前承载 T02 聚合审计代码与 protocol；本次新增 full-population audit 仍待独立审阅与 PR。crosswalk 实现另开单主题 PR，正式标注工具及盲审结果再分别拆 PR。每个 PR 均附有限总体、输入摘要、复算命令和语义/权利限制。

### Q2 — T04 新开发/确认性 WSD 门

**已有事实**：训练所用 `emotion_xpu` Conda 有 PyTorch 2.12.0+xpu 与可用 Intel Arc XPU；379 条 gold-covered train 目标上的 A/B/C/D 结构 epoch 可重复，训练输入和 checkpoint SHA 相同。这证明训练工程路径，不证明 WSD 增益。全候选编码、token alignment、训练/推断接口与文档簇不确定性已分步实现；既有 SemCor dev 经多轮试点重复使用，开发结果只能算探索。

**下一动作**：

1. 完成新候选语料/评测的许可和来源家族审查，禁止因“公开可下载”推断可训练/再分发。
2. 冻结 WN3.0 sense key ↔ OEWN ID mapping 表版本、覆盖分母、拆分/异常类别；不使用 gloss 模糊匹配补 gold。
3. 预先固定新开发数据、候选构造、不评分失败处理、共同 token/算力预算、A/B/C/D 序列化、种子、主要比较 D−B、置信区间和停止规则。
4. 仅在新开发集做一次计划内调试；报告按目标配对、按来源/文档簇重采样的区间、不同种子波动、全候选/缺失候选分母、长尾/相近义项子组与失败分析。
5. 只有独立来源、许可、映射和协议都通过后，才解封一次保留评估。外部 LLM 基线须固定版本、输入、成本及许可；旧 dev 和测试数据不得用于阈值选择。

**PR 切分**：当前候选兼容与数据接口变更各自留在对应 `codex/t04-*` 主题分支；后续 source/rights audit、冻结协议、评估器和最终一次性评分分支分开。PR 状态必须从当前 GitHub 事实核验，分支推送不等同 PR。

### Q3 — T01 ToLogic 语义审阅

- 六例有限候选合计 455，指定 reference expression 可匹配、独立枚举 replay 一致；want 的 `be without` 一例 130 候选，112 有显式外部 `without` 调用、18 无显式调用或否定算子。`without` 是用户提供的接口，不在原 85 basis。
- 先冻结候选可接受性、AND/OR 结构、变量/角色方向、参数绑定和无法判断标签；旧 20 项仅用于试标/流程调整。
- 待两位审阅者独立判断并仲裁后，报告分歧、候选覆盖和错误类型；在新增案例与独立测试形成之前，不训练 ranker 或声称泛化。

### Q4 — T03 知径 Demo 的解释链检查

- 保持现有 `concept-dictionary/`，固定任务覆盖单步定义、多个完整 OR 分支、多步依赖、循环/无路径、方向与否定结构。
- 记录目标义项、用户已知概念集、路径条件、展示结果和预期断点；机器检查输出路径是否来自合法分支、AND 前提是否完整、替代支路是否丢失。
- 做键盘、窄屏和交互状态可恢复检查，优先修复实际可复现问题并单独 PR。模拟用例结果只支持功能结论；真实学习效果需另行设计并先经用户把关。

### Q5 — T05 认知发展数据可行性

- 建立 Wordbank、CHILDES、测试级 AoA 数据的公开版本、访问方式、许可、样本语言/年龄、测量单位、词形/义项粒度和可复算引用表。
- 先用许可允许的最小样本估计 lemma/POS/sense 对齐率与歧义；严禁按出生年代、词典义项序号或机器猜测直接填成人类习得标签。
- 只有目标与许可可行后，先做词频、具体性、词性和普通语义网络基线，再加构造结构特征；用来源分组的外部验证，报告增量预测和校准。没有外部义项级因变量时，不启动预测模型。

## 每轮更新检查清单

1. 检查当前分支、远端 head、未提交变化、PR/CI 实际状态和 ignored 产物边界。
2. 只读取当前里程碑需要的数据；明确禁止的测试/私人数据不可触碰。
3. 先定估计量、分母、来源和停止规则，再运行；固定输入与配置，保留失败分母。
4. 分清工程成功、结构观察、语义验证和人类证据，不以 “loss 降低” 或 “图更清晰”代替研究结论。
5. 更新本文件、对应专项协议及本地总报告/HTML 快照；任何计划项不得更新为完成，除非有当前可核验的运行或审阅证据。
